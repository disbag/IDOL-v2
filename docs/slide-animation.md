# Анимация перелистывания слайдов (Lookbook Home)

Документ описывает механизм переключения полноэкранных слайдов на главной странице лукбука — [`src/components/LookbookPage.jsx`](../src/components/LookbookPage.jsx). Слайды объявлены в [`src/data/lookbookData.js`](../src/data/lookbookData.js) (массив `homeSlides`).

## Идея в двух словах

Переход между слайдами — это **coverflow-эффект**: уходящий слайд уменьшается и уезжает к тому краю, откуда он появился; новый слайд въезжает с противоположного края, увеличиваясь от `86%` до `100%`. Одновременно фоновая картинка hero-секции внутри каждого слайда получает лёгкий параллакс (±8%), чтобы добавить ощущение глубины.

Анимация реализована на чистых CSS-transitions (`transform` + `transition`), без сторонних библиотек. React управляет только тем, **какие значения transform подставить** в нужный момент.

## Константы

Все константы объявлены в начале файла (`LookbookPage.jsx:12-15`):

| Константа | Значение | Что регулирует |
|---|---|---|
| `SLIDE_MS` | `1000` | Длительность перехода, мс |
| `EASE` | `cubic-bezier(0.45, 0, 0.15, 1)` | Кривая плавности (мягкий вход/выход, без резкого старта) |
| `PARALLAX` | `8` | Амплитуда параллакса фона hero, в `%` |
| `PEEK_SCALE` | `0.86` | Масштаб слайда в момент появления/исчезновения (coverflow) |

Чтобы изменить скорость или плавность — трогайте только эти четыре значения, логика ниже от них не зависит напрямую (кроме использования в строках `transition`).

## Конечный автомат состояния

Компонент `LookbookPage` хранит 4 куска состояния:

```js
const [index, setIndex] = useState(0)       // индекс активного слайда
const [prevIndex, setPrevIndex] = useState(null) // индекс слайда, с которого ушли (только во время анимации)
const [direction, setDirection] = useState(1)    // 1 = «вперёд» (next), -1 = «назад» (prev)
const [phase, setPhase] = useState('idle')       // 'idle' | 'start' | 'run'
```

`phase` — это и есть автомат:

```
        goTo()                     2×requestAnimationFrame           timeout (SLIDE_MS + 80мс)
 idle ───────────► start ───────────────────────────────► run ───────────────────────────────► idle
        (без           (кладём слайд на стартовую          (transition:'transform SLIDE_MSms EASE',
        transition,     позицию БЕЗ transition,             браузер реально анимирует)
        синхронно)      1 кадр без анимации)
```

- **`idle`** — обычное состояние. Виден только активный слайд (`index`), остальные `visibility: hidden`.
- **`start`** — длится ровно 1 кадр. Новый слайд (`index`) уже примонтирован на стартовой позиции (`translate3d(±100%) scale(0.86)`), но **без** `transition`, чтобы браузер не анимировал сам факт появления из «никуда».
- **`run`** — на следующем кадре те же элементы получают целевые значения (`translate3d(0) scale(1)`) **с** `transition`. Именно на этом шаге браузер рисует анимацию.

Два `requestAnimationFrame` подряд (`LookbookPage.jsx:462-468`) — стандартный приём, чтобы гарантированно получить два разных кадра рендера: первый — применить стартовые стили, второй — переключить на целевые с транзишном. Если сделать это в один тик, браузер может «схлопнуть» оба состояния и анимации не будет.

По окончании `run` (через `setTimeout(SLIDE_MS + 80)` **и** дополнительно через `onTransitionEnd`, см. ниже) состояние сбрасывается в `idle`, `prevIndex` — в `null`.

## Как запускается переход — `goTo(target, dir)`

`LookbookPage.jsx:481-498`. Вызывается из стрелок `SlideNav` (`onPrev`/`onNext`).

```js
const goTo = (target, dir) => {
  if (busy || target === index) return   // защита от повторного клика во время анимации

  const incoming = panelRefs.current[target]
  if (incoming) incoming.scrollTop = 0    // новый слайд всегда открывается сверху

  setPrevIndex(index)
  setDirection(dir)
  setIndex(target)

  if (prefersReducedMotion()) {           // уважаем системную настройку
    setPhase('idle')
    setPrevIndex(null)
    return
  }

  setPhase('start')
}
```

`busy` = `phase !== 'idle'` — пока идёт анимация, стрелки задизейблены (`disabled={busy}` в `SlideNav`), повторный клик игнорируется и на уровне `goTo`.

## Расчёт transform — `slideStyle()`

`LookbookPage.jsx:324-406`. Вызывается для **каждого** слайда на каждый рендер и возвращает объект `style` для его контейнера (`.home-slide`). Логика читается как таблица состояний:

| Слайд | Фаза | `transform` | `transformOrigin` | `zIndex` | `pointerEvents` |
|---|---|---|---|---|---|
| Новый (`i === index`) | `start` | `translate3d(dir·100%, 0, 0) scale(0.86)` | к тому краю, откуда въезжает | `2` | `none` |
| Новый (`i === index`) | `run` | `translate3d(0,0,0) scale(1)` | тот же | `2` | `none` |
| Новый (`i === index`) | `idle` | `translate3d(0,0,0) scale(1)` | — | `1` | `auto` |
| Старый (`i === prevIndex`) | `start` | `translate3d(0,0,0) scale(1)` (ещё на месте) | к краю, куда уедет | `1` | `none` |
| Старый (`i === prevIndex`) | `run` | `translate3d(-dir·100%, 0, 0) scale(0.86)` | тот же | `1` | `none` |
| Остальные слайды | любая | `translate3d(0,0,0) scale(1)` | — | `0` | `none`, `visibility: hidden` |

`direction` (`dir`) — это `1` при next и `-1` при prev. `incomingOrigin`/`outgoingOrigin` выбираются так, чтобы масштабирование «сжимало» слайд к тому краю экрана, к которому он физически движется — это и создаёт ощущение coverflow, а не плоского слайда.

`pointerEvents: 'none'` на активном и предыдущем слайде во время анимации не даёт кликать по контенту, пока он движется; после `idle` активный слайд получает `pointerEvents: 'auto'` обратно.

## Параллакс фона — `heroShift()`

`LookbookPage.jsx:408-417`. Отдельно от масштабирования всей панели, картинка внутри `<Hero>` (`data-hero`) сдвигается на `±PARALLAX %` относительно панели:

- Активный (новый) слайд стартует со сдвигом `-dir·PARALLAX%` и едет к `0`.
- Предыдущий слайд едет от `0` к `dir·PARALLAX%`.

Это создаёт эффект, будто фон и рамка слайда двигаются с разной скоростью (глубина). Применяется только к hero-картинке (`Hero.jsx` пропс `shift`), сама картинка ещё и всегда чуть увеличена (`scale(1.18)`), чтобы сдвиг не оголял края.

## Завершение анимации — двойная защита

Есть два независимых механизма возврата в `idle`:

1. **`setTimeout(SLIDE_MS + 80)`** (`LookbookPage.jsx:470-477`) — гарантированный fallback, срабатывает всегда.
2. **`onTransitionEnd`** (`LookbookPage.jsx:500-506`, `onPanelTransitionEnd`) — слушает реальное CSS-событие `transitionend` на **активном** слайде и, если сработало именно свойство `transform` и именно на нужном DOM-узле, сразу переводит в `idle`, не дожидаясь таймаута.

Оба пути идемпотентны (`setPhase('idle')` + `setPrevIndex(null)`), так что не важно, что сработает раньше — таймаут просто подстраховывает на случай, если `transitionend` не долетит (например, вкладка была в фоне и браузер придержал рендер).

## Доступность

`prefersReducedMotion()` (`LookbookPage.jsx:17-19`) проверяет `matchMedia('(prefers-reduced-motion: reduce)')`. Если у пользователя эта настройка включена, `goTo` пропускает фазы `start`/`run` и сразу переключает `index` с `phase: 'idle'` — переход происходит мгновенно, без transform-анимации.

## Синхронизация скролла между слайдами

Каждый слайд — независимо скроллящийся `<div className="home-slide ... overflow-y-auto">` со своим `ref` в `panelRefs.current[i]`. При переключении:

- `incoming.scrollTop = 0` в `goTo` — новый слайд всегда показывается с самого верха, даже если пользователь долистал предыдущий слайд вниз.
- `useLayoutEffect` по `[index]` (`LookbookPage.jsx:455-460`) синхронно (до отрисовки) обнуляет `scrollTop` и переустанавливает `scrollRootRef`/`heroRef`, которые нужны компоненту `Header` для логики прозрачности шапки (`opaqueAfterRef`, `scrollRootRef` в `Header.jsx`).

## Header поверх слайда

`Header` получает `invert` в зависимости от `homeSlides[index].hero.headerInvert` (или `prevIndex` во время анимации) — управляет цветом лого/иконок (тёмные/светлые) в зависимости от того, насколько светлый верх hero-картинки. Это применяется отдельно к самому Header'у, не через `slideStyle`.

## Как добавить/настроить слайд

Каждый элемент `homeSlides` (см. `lookbookData.js`) — это данные, а не JSX. Из relevant для анимации полей:

- `hero.navInvert` — светлые/тёмные стрелки `SlideNav` (белые поверх тёмного фото или наоборот).
- `hero.headerInvert` — то же самое, но для шапки сайта.
- `hero.originTop` — точка масштабирования hero-картинки при параллаксе (`scale(1.18)` от верха, а не от центра) — полезно, если важно не обрезать верх кадра.

Сама анимация переключения слайдов не требует никакой конфигурации на уровне данных — она одинакова для всех слайдов и управляется исключительно константами в начале `LookbookPage.jsx`.

## Частые правки

| Хочу | Что менять |
|---|---|
| Сделать переход быстрее/медленнее | `SLIDE_MS` |
| Сделать плавнее/резче | `EASE` (кривая cubic-bezier) |
| Сильнее/слабее «выезжание» соседних слайдов | `PEEK_SCALE` (ближе к `1` — слабее эффект) |
| Сильнее/слабее параллакс фона | `PARALLAX` |
| Убрать coverflow, вернуть плоский слайд | В `slideStyle()` убрать `scale(...)` из всех `transform`, оставить только `translate3d` |

## Известные ограничения

- Анимация — **только горизонтальный coverflow**, вертикальных/fade-переходов на этом же движке не предусмотрено.
- Одновременно может анимироваться только один переход — во время `busy` все клики по стрелкам игнорируются (это осознанное решение, не баг).
- `will-change-transform` стоит на `.home-slide` и внутреннем div hero-картинки постоянно — при добавлении новых тяжёлых слайдов с большим числом слоёв стоит проверять производительность на слабых устройствах.
